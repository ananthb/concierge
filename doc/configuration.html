Configuration & secrets.

Every environment variable, secret, binding, OAuth redirect, webhook URL, and cron trigger Concierge expects. All sensitive values are stored as Cloudflare Workers secrets via wrangler secret put; non‑sensitive values live in the [vars] block of wrangler.toml.

Total secrets 14 required · 4 optional Env vars 8 Bindings 6
i
Setting secrets

Use the Wrangler CLI: wrangler secret put SECRET_NAME. You’ll be prompted to enter the value securely. Secrets are encrypted at rest by Cloudflare and exposed to your Worker as environment variables.

Environment variables

The Worker reads three groups of plain‑text vars: a static default in wrangler.toml, deployment‑specific values injected at deploy time, and optional integration overrides set in the dashboard.

Secrets that are no longer read

ENCRYPTION_KEY, INSTAGRAM_VERIFY_TOKEN, DISCORD_PUBLIC_KEY, DISCORD_APPLICATION_ID and DISCORD_BOT_TOKEN were required by earlier revisions. Nothing reads them now: the encryption key existed to seal per-tenant Instagram tokens, and WhatsApp uses one platform token that needs no sealing. Remove them with wrangler secret delete.

Cloudflare Queues

Two queues must exist before deploy:

  • concierge-safety: producer + consumer for the persona safety classifier. The Worker enqueues a SafetyJob on each persona save and consumes the same queue via #[event(queue)].
  • concierge-safety-dlq: dead‑letter queue for safety jobs after 3 retries. Inspect failures here when persona checks stop completing.
bash terminal 
wrangler queues create concierge-safety
wrangler queues create concierge-safety-dlq

Local wrangler dev works without queues configured: safety_queue::enqueue logs and falls through, leaving personas in Pending until you deploy against a properly bound environment.

Locale & supported languages

Every tenant has a BCP‑47 locale tag (Tenant.locale) plus an independent currency override. Currently shipped: en-IN (default; Indian‑style number grouping, INR currency) and en-US (Western grouping, USD). Locale is set at signup from the request’s Accept-Language header, falling back to cf-ipcountry, then to en-IN. Both are changeable afterwards on the dashboard’s Settings tab, which posts to PUT /api/settings — the single write path for the pair since the unused PUT /api/billing/currency was removed. That endpoint rejects any tag outside the shipped set rather than falling back to en-IN silently, so a saved value always means what it says.

Adding a new locale is a drop‑in change: place a translated messages.ftl at assets/locales/{tag}/, register the tag in src/i18n.rs::Translator::new and src/locale.rs::Locale::from_request, then rebuild. CLDR data for number / currency formatting ships automatically via icu4x’s compiled_data feature. AI‑generated reply content stays English regardless of the UI locale.

Conversation timing

Three per‑tenant knobs control how the worker treats a customer thread. They live on OnboardingState.conversation (a ConversationConfig) in KV at onboarding:{tenant}; each is Option<u32> and falls back to a constant in src/prompt.rs when unset. GET and PUT /api/settings read and write them, and the dashboard’s Settings tab is the UI. Each field is three-valued on the wire: absent leaves the stored value, null clears the override back to the default, and a number sets it. An empty box in the form sends null, which is the only way to return a knob to its default.

ConversationConfigper‑tenant runtime knobs 3 knobs
FieldBoundsDefaultEffect
idle_gap_mins 5…1440 mins 360 (6 h) — DEFAULT_CONVERSATION_IDLE_GAP_MINS After this much customer silence, the next inbound starts a fresh conversation: history clears, handoff state is wiped, the persona replies normally.
handoff_cooldown_mins 5…1440 mins 60 — DEFAULT_HANDOFF_COOLDOWN_MINS After the model emits [[HANDOFF]], replies switch to the holding‑pattern voice for this long; past it, the worker stays silent.
max_history_messages 1…200 turns 20 — DEFAULT_CONVERSATION_MAX_MESSAGES Cap on the number of recent (role, content) turns passed to the reply model on each AI call.

Cross‑field invariant: idle_gap_mins > handoff_cooldown_mins. Set the other way round, an active handoff can be wiped before its cooldown ends. PUT /api/settings enforces it against the resolved pair, so lowering only the gap is refused when it would collide with the default cooldown the request never mentioned.

OAuth redirect URIs

Register these in the respective developer consoles:

  • Google: https://your-domain/auth/callback — the only sign-in provider.
  • Meta: https://your-domain/whatsapp/signup/callback, for the Embedded Signup flow that attaches a customer’s number to your WABA. This is not a sign-in redirect, but Meta needs it registered as a valid OAuth redirect URI on the app.

The Facebook Login and Instagram callbacks that earlier revisions registered (/auth/facebook/callback, /instagram/callback) are gone. Both routes now 404; you can remove them from the Meta app.

Cron triggers

One cron, hourly at 0 * * * *: it re-rolls the landing-page demo personas when the operator-configured cadence has elapsed, and is a single KV read when it isn’t due. Configured in the [triggers] section of wrangler.toml and mirrored in src/scheduled.rs, which dispatches on the cron string.

Two crons were removed: a 15-minute approval-digest sweep (which expired stale queued drafts and emailed digests) and a daily Instagram token refresh.

toml wrangler.toml · partial 
# Identity
name = "concierge"
main = "worker-shim.mjs"
compatibility_date = "2024-01-01"

# Plain-text variables (deployment-specific values come in via --var at deploy time)
[vars]
ENVIRONMENT           = "production"

# Bindings
[[d1_databases]]
binding      = "DB"
database_name = "concierge"
database_id   = "…"

[[kv_namespaces]]
binding = "KV"
id      = "…"

[ai]            binding = "AI"
[[send_email]]   name    = "EMAIL"

# The Elm bundle, boot.js, the CSS, and the prerendered marketing pages.
# A request matching a file here is answered from the edge and the Worker
# is never invoked — which is why public/_headers exists to set the CSP
# for those routes. html_handling defaults to auto-trailing-slash, so
# /pricing serves public/pricing.html.
[assets]
directory = "./public"

[[durable_objects.bindings]]
name       = "REPLY_BUFFER"
class_name = "ReplyBufferDO"

# ApprovalsDO was deleted; the migration tells Cloudflare to drop the
# class. Removing only the binding leaves it orphaned and the deploy fails.
[[migrations]]
tag             = "v3"
deleted_classes = ["ApprovalsDO"]

# Persona safety classifier
[[queues.producers]]
queue   = "concierge-safety"
binding = "SAFETY_QUEUE"

[[queues.consumers]]
queue             = "concierge-safety"
max_batch_size    = 10
max_batch_timeout = 5
max_retries       = 3
dead_letter_queue = "concierge-safety-dlq"

# Hourly: re-roll the demo personas when the cadence has elapsed
[triggers]
crons = ["0 * * * *"]
!
Rotating secrets

Nothing stores a per-tenant token any more, so there is no secret whose rotation forces customers to reconnect. WHATSAPP_VERIFY_TOKEN can be rotated independently — update it in the Meta Developer Console at the same time. Rotating WHATSAPP_ACCESS_TOKEN stops all outbound messages until the new value is set, since it is the only token the platform sends with.
